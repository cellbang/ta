## Minor Changes

- Work handed over comes back: once the agent is done (or the round of the channel is over), the conversation that handed it over gets a receipt with its last answer, a card "@dev answered the hand-over" whose text its model reads, kept until the conversation opens when it is not open. The menu of a conversation in a list has Hand over to…, which opens it and asks Ta there; and an ask of the + is handed over when Ta asked the user something first and wrote the brief a turn later. (`@celljs/ta-channels`)
- Cloud workspaces: the agent's commands there have no network by default, or reach only the hosts the user lets out (Settings → Remote hosts), held in a network of their own where the machine allows it (bubblewrap, unshare, macOS sandbox), with one button to make Ubuntu 24.04 allow it. Dependencies are installed before the agent goes on (dev container commands or lock files), with the network and the vault's secrets marked for installing, which the agent never gets. (`@celljs/ta-client`, `@celljs/ta-cloud-handoff`, `@celljs/ta-gateway`, `@celljs/ta-host`, `@celljs/ta-protocol`, `@celljs/ta-secrets`, `@celljs/ta-web`)
- Keys of model services go into the vault: an API key in auth.json is kept in the vault and auth.json reads it from there, so it follows your account to your devices. Your cloud workspaces borrow the keys you let them use (by default every model key; a switch per key in the vault), in memory only, given back when the workspace is removed. When the cloud cannot use the model of a conversation it moves, it goes on with one it can and says so; when it can use none, the conversation stays on this computer. (`@celljs/ta-cloud-handoff`, `@celljs/ta-host`, `@celljs/ta-protocol`, `@celljs/ta-secrets`, `@celljs/ta-sync`)

## Patch Changes

- A machine reached by ssh becomes a cloud workspace with one click (Settings → Remote hosts): Ta installs itself there from npm, keeps its service running on 127.0.0.1 of that machine, and reaches it through ssh, starting it again when it stopped. Conversations can then go on there while this computer is away, without a hosted sandbox. (`@celljs/ta-cloud-handoff`, `@celljs/ta-exec`, `@celljs/ta-host`, `@celljs/ta-protocol`, `@celljs/ta-web`)
- Remote hosts is simpler: one row a machine, with what belongs to it under it. A machine reached by ssh has the switch “Go on here while this computer is away” (it was a hidden button that made it a second row, a cloud workspace), and once on, its network and the ports forwarded from it. A Ta gateway, which few have, is last, asking only its address and token, saying where the token is made. What a host is doing (installing Ta, starting it) is said in its row, no longer as a line floating over the page that stayed after it was done; the port Ta forwards for the service of a cloud workspace is no longer listed. (`@celljs/ta-cloud-handoff`, `@celljs/ta-host`, `@celljs/ta-protocol`, `@celljs/ta-web`)
- A shell command of a reply goes to the terminal: a block of `bash`, `zsh`, `powershell` and the like (and a command a tool ran) has a button beside Copy that puts it at the prompt of the terminal shown in the workbench, opening one when there is none, without running it: the user reads it and presses Enter. The `$ ` of a block written as typed is left out. Web extensions add such buttons with `registerCodeMenu(block => items)`, `block` being `{ language, code }`. (`@celljs/ta-extensions`, `@celljs/ta-web`, `@celljs/ta-workspace`)
- Programs of the terminal come back after Ta restarts, by the Program Resume Protocol (OSC 7577) that pi 1.7 speaks. Each shell of zsh or bash on this computer gets a token of its own in `OSC7577_TOKEN`; a program reports the command that brings it back, signed with it, and ta serve checks the report as the protocol says (mac, time window, strict form, a pid of this user that runs) and keeps it in `terminal-resume.json` of the agent directory, readable by the user alone. Once Ta started again (a restart, an update) or the page of a terminal went, `TaTerminalServer.resumeTerminals` opens those terminals again, each command run by the shell after its startup files from a file of its arguments, never parsed as shell source; when it ends the user has the shell. Terminals the user closed, programs the user quit, and a command brought back that did not report again do not come back. ta-workspace calls it as the terminal opens and when the page reconnects (`pi.onReconnect`, new), replacing the tabs of before; Settings → Terminal turns it off. Ids of terminals are now those of a run of Ta, so a page that outlived a restart does not take a new shell for an old one. (`@celljs/ta-extensions`, `@celljs/ta-host`, `@celljs/ta-protocol`, `@celljs/ta-web`, `@celljs/ta-workspace`)
- pi 1.7.0 (all `@earendil-works/pi-*` packages) and the updates within their major versions: vite 8.4.0, react-router 7.18.7, lucide-react 1.83.0, mermaid 12.4.0, @types/ali-oss 6.23.5. Ta's patch of pi is made again for 1.7.0. What users of Ta notice from pi 1.6.1 and 1.7.0: `ta` run in a terminal of Ta reports how to bring its session back (OSC 7577, with its tools and flags), so the terminal reopens it after Ta restarts; more temporary provider failures are retried (HTTP 525, "temporarily unavailable", Anthropic `api_error` while streaming, empty responses); sessions with very many entries load again; the bash tool keeps its truncated output when the temp file cannot be written; `!!` commands no longer count toward compaction; an invalid `models.json` is reported. pi no longer has install telemetry: `TA_TELEMETRY` (`PI_TELEMETRY`) is gone, nothing of pi reports to pi.dev. (`@celljs/ta-harness`, `@celljs/ta-host`, `@celljs/ta-web`, `@celljs/ta`)
- Open to others: open an agent of yours by a link. Others use it from a browser, each in conversations of their own that run on your computer and its model, apart from yours and each other's, at once; within plans you set (a trial, packs, monthly with a cap a day), paid offline or by your WeChat payment code and opened once you confirm. Members gets the role User, links that say what they open, and Discover → Open to others. (`@celljs/ta-harness`, `@celljs/ta-host`, `@celljs/ta-manual`, `@celljs/ta-offer`, `@celljs/ta-protocol`, `@celljs/ta-relay`, `@celljs/ta-team`, `@celljs/ta`)
